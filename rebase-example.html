Rebase your work

Rebase replays your branch commits on a newer base. The result is often a straight, easy-to-read line of history.

Replay commits on a new base

Update your feature branch after the main branch moves forward.

  1. 1

    Update

    Get current main.

    git fetch origin
  2. 2

    Switch

    Move to your branch.

    git checkout topic
  3. 3

    Replay

    Use the newer base.

    git rebase main
  4. 4

    Review

    Check the new history.

    git log --oneline

Basic syntax

git checkout docs/new-lesson
git rebase main

Git replays each commit from your branch on top of main. The replayed commits receive new IDs.

Resolve or cancel a conflict

If a commit conflicts, edit the files, stage the resolutions, and continue. To return to the state before rebase, abort instead.

git add resolved-file.html
git rebase --continue
git rebase --abort
Keep shared work safe: avoid rebasing commits that other people already use unless the team agrees to rewrite that history.
