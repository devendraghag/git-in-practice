Branches and remotes

Branches are local lines of work. A remote is another repository you communicate with when fetching, pulling, or pushing.

git clone

Downloads a remote repository and its history into a new local folder, usually setting its remote name to origin.

git clone https://github.com/OWNER/REPO.git
git clone https://github.com/OWNER/REPO.git git-practice

Typical first step when joining an existing project. Communicates with the remote and creates local files.

git fetch

Downloads new commits and branch pointers without merging into your current branch or changing working files.

git fetch origin
git log --oneline --all --decorate

Fetch first when you want to inspect updates before integrating them.

git pull

Fetches remote updates and integrates them into the current branch (often by merge; configuration can use rebase). It contacts a remote and may update local files/history.

git pull origin main
git pull --rebase origin main

Commit or stash your own work first, then resolve any conflicts carefully.

git push

Sends local commits to a remote branch. It communicates with the remote and normally refuses to overwrite commits you do not have.

git push -u origin main
git push origin docs/branch-workflow
git push origin v1.0

-u sets an upstream for future pushes. Push tags explicitly or use git push --tags.

git merge

Combines another branch into the branch currently checked out. It updates local history and possibly files; by itself it does not contact a remote.

git checkout main
git merge docs/branch-workflow

Resolve conflicts, stage resolutions, then finish the merge commit if Git asks.

git rebase

Replays your branch commits on a new base for a linear local history. Replayed commit IDs change.

git checkout docs/new-lesson
git rebase main

Do not rebase commits others depend on without agreement. For conflicts, fix files, run git add, then git rebase --continue; git rebase --abort returns to the prior state.

git cherry-pick

Copies one chosen commit onto the current branch as a new commit. Local history changes; the source branch is not merged.

git checkout main
git cherry-pick a1b2c3d

Useful for one focused fix. On conflicts, resolve, stage, and run git cherry-pick --continue.

Check which remote is configured

Use git remote -v to see the fetch and push URLs. This is a local inspection command. A new local repository can be connected with git remote add origin https://github.com/OWNER/REPO.git.

A collaboration loop

git status
git fetch origin
git log --oneline --graph --decorate --all
git pull --rebase origin main
git add changed-file.html
git commit -m "Document remote workflow"
git push

Fetch and inspect; integrate updates; make focused local commits; push when ready. Network access is used at fetch, pull, and push.
