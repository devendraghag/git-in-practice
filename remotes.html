Lesson 03 / Working together

Branches and remotes

Branches let you work on ideas separately. Remotes let you exchange commits with GitHub and your teammates.

The collaboration loop

Get updates, integrate carefully, then share your commits.

  1. 1

    Fetch

    Download new remote history.

    git fetch origin
  2. 2

    Inspect

    Review branches and commits.

    git log --oneline --all
  3. 3

    Integrate

    Pull updates or merge a branch.

    git pull --rebase
  4. 4

    Share

    Send your commits upstream.

    git push

Fetch, pull, push, and clone contact a remote. Merge, rebase, and cherry-pick change local history.

Connect and sync

Remote commands exchange commits; review which local or remote state they change.

git clone

Downloads a repository and its history into a new local folder. Git usually names the remote origin.

git clone https://github.com/OWNER/REPO.git
git clone https://github.com/OWNER/REPO.git git-practice

Use it when starting from an existing project. It contacts the remote and creates local files.

Contacts remoteCreates local copy

git fetch

Downloads new commits and branch pointers without merging them into your current branch or changing working files.

git fetch origin
git log --oneline --all --decorate

Fetch first when you want to inspect updates before integrating them.

Contacts remoteDoes not merge

git pull

Fetches remote updates and integrates them into your current branch, usually by merge. Configuration can make it rebase instead.

git pull origin main
git pull --rebase origin main

Commit or stash your own work first. Resolve any conflicts carefully.

Contacts remoteUpdates local files/history

git push

Sends local commits to a remote branch. Git normally refuses to overwrite commits you do not have.

git push -u origin main
git push origin docs/branch-workflow
git push origin v1.0

-u records the upstream for future pushes. Use git push --tags when you intend to publish all tags.

Contacts remotePublishes commits

Combine local work

Choose a method based on how much work you want to bring across.

git merge

Combines another branch into the branch currently checked out. It updates local history and possibly files, but does not contact a remote by itself.

git checkout main
git merge docs/branch-workflow

If there are conflicts, edit the files, stage the resolutions, and finish the merge commit.

LocalCombines branch history

git rebase

Replays your branch commits on a new base to create a linear history. The replayed commit IDs change.

git checkout docs/new-lesson
git rebase main
git rebase --continue
git rebase --abort

For conflicts, resolve the files, stage them, then continue. Abort returns to the pre-rebase state.

Shared history: avoid rebasing commits others depend on unless your team agrees.
LocalRewrites branch commits

git cherry-pick

Copies one chosen commit onto the current branch as a new commit. The source branch is not merged automatically.

git checkout main
git cherry-pick a1b2c3d
git cherry-pick --continue

Useful for bringing one focused fix across. If conflicts occur, resolve and stage them before continuing.

LocalCopies one change

Check the configured remote

git remote -v shows where fetch and push go. A new local repository can be connected with:

git remote add origin https://github.com/OWNER/REPO.git
Example: a careful sync before sharing
git status
git fetch origin
git log --oneline --graph --decorate --all
git pull --rebase origin main
git add changed-file.html
git commit -m "Document remote workflow"
git push

Fetch and inspect first, integrate remote changes, make a focused commit, then push.
