A useful picture of Git

Your working folder contains files you edit. The staging area is a shortlist of changes for the next snapshot. A commit saves that snapshot in local history. A remote is another copy, often hosted on GitHub.

working files  →  staging area  →  local commits  ⇄  remote repository
   edit             git add         git commit        fetch / pull / push

Most commands in this guide work locally. git fetch, git pull, and git push communicate with a remote. git clone downloads a repository and creates a local copy.

Follow the normal loop

  1. Check the project and branch with git status.
  2. Edit focused files, then review with git diff.
  3. Stage selected files using git add path/to/file.
  4. Save a snapshot with git commit -m "Add command guide".
  5. Share commits with git push; receive teammates’ updates with git pull.

Commit messages are short summaries, usually starting with a verb: “Add command guide,” “Fix broken navigation,” or “Document branch workflow.” Focus each commit on one idea.
