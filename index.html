A simple picture of Git

Your working folder holds the files you edit. The staging area is a shortlist of changes for your next snapshot. A commit saves that snapshot in local history. A remote is another copy, often hosted on GitHub.

working files  ->  staging area  ->  local commits  <->  remote
    edit              git add         git commit       fetch / pull / push

Most commands in this guide work locally. git fetch, git pull, and git push communicate with a remote. git clone downloads a repository and creates a local copy.

The everyday loop

  1. Check your branch and changes with git status.
  2. Edit a few related files, then review them with git diff.
  3. Choose what belongs in the next snapshot with git add path/to/file.
  4. Save it locally with git commit -m "Add command guide".
  5. Share your work with git push; receive teammates' updates with git pull.

Good commit messages say what changed: Add command guide, Fix broken navigation, or Document branch workflow. Keep each commit focused on one idea.

If you need to pause tracked edits, git stash push -m "short task note" saves them temporarily so you can switch tasks and restore them later.
