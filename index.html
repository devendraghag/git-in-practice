Your first Git workflow

Follow a change from your computer to a shared remote.

  1. 1

    Inspect

    See what changed and which branch you are on.

    git status
  2. 2

    Stage

    Pick the files that belong in this snapshot.

    git add page.html
  3. 3

    Commit

    Save a named snapshot in local history.

    git commit -m "Add guide"
  4. 4

    Share

    Send your new commit to the remote repository.

    git push

The first three steps happen locally. Sharing uses your configured remote, such as GitHub.

A simple picture of Git

Git keeps your edits, selected changes, saved history, and shared copy in separate places.

Your working folder holds the files you edit. The staging area is a shortlist for the next snapshot. A commit saves that snapshot in local history. A remote is another copy, often hosted on GitHub.

Working files Staging area Local history Remote copy

Most commands in this guide work locally. git fetch, git pull, and git push communicate with a remote. git clone downloads a repository and creates a local copy.

A good everyday rhythm

Small, reviewable steps make Git easier to understand and safer to use.

  1. Check your workUse git status to see your branch and changes.
  2. Review your editsUse git diff before choosing what to save.
  3. Stage only related filesUse git add path/to/file to select them.
  4. Save a clear snapshotUse git commit -m "Add command guide".

Write useful commit messages. Start with a verb and describe one change.

Add command guideFix broken navigationDocument branch workflow

To pause tracked edits and switch tasks, save them with git stash push -m "short task note". Share finished commits with git push; receive teammates' updates with git pull.
